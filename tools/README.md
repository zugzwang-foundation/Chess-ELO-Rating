# tools/

Status: DRAFT — utilities, not the rating engine.

## checks/ — the automated check

The workflow `.github/workflows/check.yml` runs on every pull request to `main`; a pull request is merged only when it is green (`docs/decisions/D-0004_merge-policy.md`). The same checks run locally from the repository root:

| Check | Command | What it enforces |
|---|---|---|
| (a) | `python3 tools/checks/check_outputs.py` | every script registered in `analysis/outputs.json` reproduces its committed output byte for byte; every `analysis/*.py` is registered. Add `--all` to also rerun the scripts that read raw data under `data/` (`"needs_data": true`) and the slow ones (`"slow": true`, the simulator) |
| (b) | `python3 -m pytest -q` | the test suite under `tests/`, configured in `pyproject.toml`: the SPEC-L0 acceptance tests A-1 to A-10 against the engine in `src/layer0/` |
| (c) | `python3 tools/checks/check_refs.py` | relative links and repository paths in code spans exist (records, and documents marked RATIFIED, may name a path that existed earlier in git history); `[R n]`, `[V k]`, `[VT k]`, `[VP k]`, `[E n]` and `[T n]` references resolve against the research report, the three verification sweeps, the evidence reports and the current technical annex |
| (d) | `python3 tools/checks/check_wordcount.py` | the body of the current proposal is at most 4,500 words by ELO-2's strict count, and the current brief at most 900 words (D-0005) |

Python standard library only (pytest for (b)). Python 3.12 in CI.

## compare_event.py — one event under FIDE's rules and under rung 2

`tools/compare_event.py` (`docs/specs/SPEC-COMPARE_v1_0.md`) reads an event file from `tools/events/` and prints, per player, the rating change under (a) FIDE today, computed by the Layer-0 engine, and (b) rung 2, the fitted table of `params/table_fit_2026-10.yaml` with the same K. `--csv FILE` also writes a CSV; `--rung4` and `--rung5` accept only `off` until Layer 1 exists. `tools/set_results.py` records a round's results in an event file.

| Event file | Event |
|---|---|
| `tools/events/us_championship_2025.json` | 2025 U.S. Championship (the check: column (a) equals FIDE's calculation) |
| `tools/events/us_championship_2026.json` | 2026 U.S. Championship, 9–21 October 2026 |
| `tools/events/us_womens_championship_2026.json` | 2026 U.S. Women's Championship, 9–21 October 2026 |

## compare_pilot.py — rung 2 with the guard and, labelled PILOT, rung 5

`tools/compare_pilot.py` (Freeze 2, `docs/decisions/D-0010_freeze-2.md`) reads the same event files and prints, per player, (b) the change under rung 2 with R17's guard (`src/layer2/guard.py`) and today's K, which equals `tools/compare_event.py`'s column (b) wherever the guard does not bind, and (p), labelled PILOT, the same with rung 5: an eligible junior's opponents who are not eligible use RX_j = R_j + c_j, the juniors' own expectations published ratings (R8). The eligibility flags and c_j are frozen in `params/rung5_us2026.json`, written by `analysis/us26_rung5_extract.py` from a Layer 1 fit on games to September 2026. `tests/test_compare_pilot.py` checks it against the frozen tool.

**Run once, after the event ends** (the operator's decision of 2026-10-09; it replaces the per-round rerun of the ELO-3 brief). Freeze 2's page, `docs/evidence/E3_us-championship-2026.md`, prints the SHA-256 of Freeze 1's files and, as a static record since ruling R52 (`docs/decisions/D-0012_pre-results-amendments.md`), the 89 hashes of Freeze 2 as they stood at the tag `freeze-2`; it is generated by `analysis/e3_freeze2_record.py`, which runs Freeze 2's page script `analysis/e3_us_championships.py` unchanged. Freeze 2's comparison is superseded by Freeze 3 and Freeze 3a (below). The page prints the main table (columns (a) and (b) of Freeze 2), the PILOT table and the values of the blanks as D-0010 fixed them.

## compare_event_v3.py — Freeze 3: columns (a), (b), (b0) and the PILOT table on (b)

`tools/compare_event_v3.py` (Freeze 3, `docs/decisions/D-0011_rulings-and-freeze-3.md`, part B) reads the same event files and prints, per player, (a) FIDE today through `tools/compare_event.py` unchanged; (b) rung 2 v2 as session ELO-6 left it: the table calibrated by level (`params/table_fit_2026-10b.yaml`, E11), the narrowed guard where `params/guard_2026-10b.yaml` applies it (`src/layer2/guard_v2.py`, E12) and each game's K multiplied by the table's printed slope ratio m(L) of the game's level band (R32); (b0) rung 2 exactly as Freeze 2 pre-registered it, labelled "first pre-registration, superseded"; and, separately and labelled PILOT, rung 5 on top of (b) with the frozen inputs of `params/rung5_us2026.json`. `tests/test_compare_event_v3.py` checks column (a) against FIDE's 2025 calculation and (b0) against Freeze 2's column (b).

## compare_event_v3a.py — Freeze 3a: column (b′) and the rule for a game not played

`tools/compare_event_v3a.py` (Freeze 3a, `docs/decisions/D-0012_pre-results-amendments.md`) adds the column (b′), "v2 table and narrowed guard at today's K", §10's main column (R44, R45): `tools/compare_event_v3.py`'s column (b) with the slope ratio switched off, so computed only from Freeze 3's table and guard and Layer 0's K. It prints (a), (b′), (b) (Freeze 3's column with K × m, as pre-registered) and (b0) side by side, and Freeze 3's PILOT table unchanged. A game marked not played is excluded from every column, and an event is complete when every game of rounds 1–11 has a result or that marker (R43). `tests/test_compare_event_v3a.py` checks (b′) against column (b) without m and the rule for a game not played on a synthetic event file (`tests/fixtures/events/`), never on the 2026 files.

## compare_event_v3b.py — Freeze 3b: what the pairings fix, the PILOT on (b′) and the forecast test

`tools/compare_event_v3b.py` (Freeze 3b, `docs/decisions/D-0014_forecast-test-and-rulings.md`, part A) runs Freeze 3a's and Freeze 3's tools unchanged and adds three things: per player, every figure the pairings and the October ratings fix (R55: (b′) − (a), (b0) − (a), the PILOT's difference, and for (b) − (a), which m makes depend on the score, its values with no point scored and with every game won), computed on copies of the event with placeholder results that must agree; the PILOT rebuilt on (b′) at today's K (R56); and the forecast test (R54), the per-game three-outcome log-loss and expected-score Brier score of (a)'s and (b′)'s expectations with bootstrap intervals over games and over players, per event and pooled. (a)'s three outcomes use the draw rates of `params/draw_rate_2026-10b.json`, written by `analysis/us26_draw_rate_extract.py` (needs `data/`). `tests/test_compare_event_v3b.py` checks the identities and the arithmetic on the synthetic event and the 2025 event, never on 2026 results.

**After the event (Freeze 3b).** After the last round, read each round's results from the official page (https://saintlouischessclub.org/event/2026-us-chess-championships/) and enter them board by board, one command per round, using `tools/events/us_womens_championship_2026.json` for boards 7–12: `1-0`, `1/2-1/2` or `0-1`; `unplayed` for every game §5.1 of the rating regulations does not count or rate, as D-0013 reads it (not played, a player made no move, declared unrated by the time of entry); `-` for no result yet. Then regenerate both pages once, with the project's Python (`.venv/bin/python`, 3.12); `docs/evidence/E13_us-championship-2026-freeze-3.md` prints the tables, the forecast test and the blanks of the proposal's §10 as D-0012 and D-0014 define them once both events are complete; its manifest of the frozen files must equal the one D-0016 records (check (a‴), `tools/checks/check_freeze3d.py`), Freeze 3c's the one D-0015 records (check (a″), `tools/checks/check_freeze3c.py`), Freeze 3b's the one D-0014 records (check (a′)) and Freeze 3a's the one D-0012 records (check (a)). D-0015 fixes how the forecast test is read: the primary endpoint is the pooled Brier difference with its interval over games, read with one of three sentences fixed in advance (`tools/compare_event_v3c.py`, Freeze 3c); D-0016 confirms it and reads every log-loss line with the crossed interval over players (R66), which `tools/compare_event_v3d.py` (Freeze 3d) adds for the two secondary log-loss lines:

## data/ — downloads and conversions

Raw and converted data live under `data/` at the repository root, which is never committed (`.gitignore`): FIDE's lists carry no data licence and are analysed, never redistributed [V 3]. Only aggregates computed from them are committed, under `analysis/aggregates/`.

| Script | What it does |
|---|---|
| `tools/data/fetch_fide_lists.py` | Downloads FIDE's monthly lists (TXT in zip) for one time control and a range of months into `data/raw/fide/<tc>/`, one request at a time, recording URL, UTC time, size and SHA-256 in `data/raw/fide/MANIFEST.tsv` |
| `tools/data/convert_fide_lists.py` | Converts each list into `data/interim/fide/<tc>/YYYY-MM.tsv` (id, rating, games, K, year of birth, sex, federation, flag, title), locating the fixed-width columns from each file's header |
| `tools/data/fetch_lichess_broadcasts.py` | Downloads the Lichess broadcast archive (monthly PGN, zstd; CC BY-SA 4.0 [V 4]) into `data/raw/lichess_broadcast/`, checking each file against the published SHA-256 sums and recording it in a manifest |
| `tools/data/fetch_fide_calculations.py` | Selects players and periods deterministically from the converted lists (`select`, and `select-cross` for periods holding an event that started under an earlier list, from the broadcast tours), fetches FIDE's published per-player calculations one at a time at least 10 s apart (`fetch`; raw responses under `data/raw/fide_calculations/`), and assembles `tests/fixtures/fide_calculator/published_multi_event_periods.json` (`assemble`); opponents' names are never recorded |
| `tools/data/convert_broadcasts.py` | Converts each month into `data/interim/broadcast/YYYY-MM.tsv`: one line of game headers per game, no moves (needs the `zstd` command) |
| `tools/data/fetch_top100_calculations.py` | For the top-100 replay (`docs/specs/SPEC-TOP100_v1_0.md`): `plan` lists the top 100 active players of the October 2026 standard list and every list from 2020-02 to 2026-10 on which each has rated games (3,685 pages); `fetch` gets each of FIDE's per-player calculations once, three seconds apart, caches it under `data/raw/fide_calculations/` and never fetches it again, logs every request in `MANIFEST_top100.tsv` and stops at the first refusal |
| `tools/data/assemble_history_fixtures.py` | Writes `tests/fixtures/fide_history/published_periods.json` from the cached calculations: for each rule that changed between February 2020 and October 2026, the first period that shows it (cap marks, the one-upgrade clause, the 2650 exemption, the rounding of a negative half point), opponents by the rating FIDE used, never by name |
| `tools/data/assemble_tested_readings.py` | Writes `tests/fixtures/fide_history/tested_readings.json` from the same cached calculations and lists (ruling R63, SPEC-L0 v1.2 §11): every tournament of 1 March 2024 to 30 September 2025 in which a favourite had two or more differences beyond 400 (F-H06), every period on a list to December 2021 whose sum ended in a negative half point (F-H07), and the tournaments whose K differs from the previous list's (F-H08); no name, FIDE ID or event |
| `tools/data/fetch_fide_handbook.py` | Fetches chapters of FIDE's handbook once each, three seconds apart, into `data/raw/fide_site/handbook/` with a manifest, for the transcriptions of `docs/research/VERIFICATION_RATING-REGULATIONS-ARCHIVE.md` |
| `tools/data/fetch_fide_old_lists.py` | FIDE's standard lists of January 2001 to January 2015, once each, into `data/raw/fide_old/standard/` with a manifest: the old file names FIDE still serves, the periods of FIDE's download page of 2022 (Internet Archive copy); at least four seconds between requests to ratings.fide.com, across runs (its first eighteen requests did not keep that: SPEC-GREATS §3) |
| `tools/data/convert_fide_old_lists.py` | Converts those lists, and OlimpBase's transcription of FIDE's lists of 1971 to 2001, into per-list TSV files under `data/interim/` (id, name, fed, rating, games, flag, title) |
| `tools/data/convert_fide_toparc.py` | Converts FIDE's printed open top-100 lists of July 2000 to December 2019 (Internet Archive copies fetched with `tools/data/fetch_probe.py`) into per-list TSV files with each player's FIDE ID, matched on FIDE's full list of the date |
| `tools/data/fetch_probe.py` | The data probe for the greats (session ELO-9, Phase 1): fetches each page once into `data/raw/probe/` with a manifest; robots.txt read once per host and obeyed; at least the gaps of `tools/data/politeness.py` between requests to a host (four seconds to FIDE's hosts, eight to the Internet Archive, three otherwise; ruling R75), across runs and tools; a refusal by FIDE stops the run; FIDE's AJAX endpoints with the headers their pages send (`--ajax`, `--post`) |
| `tools/data/politeness.py` | The session's politeness rules (ruling R75, `docs/decisions/D-0017_rulings-on-the-greats.md`): the gap each host needs (four seconds to FIDE's hosts, eight to the Internet Archive, three otherwise), measured from the last request any of the session's fetch manifests records, across runs and tools; used by `fetch_probe.py` and `fetch_greats_calculations.py` |
| `tools/data/fetch_greats_calculations.py` | For the greats' replay (session ELO-9, Phase 3; SPEC-GREATS §6): `plan` lists, for each great with a FIDE ID, the standard rating periods of April 2008 to December 2019 on FIDE's calculations index (the probe's cached index pages); `fetch` gets each of FIDE's per-player calculations once into `data/raw/fide_calculations_greats/` with a manifest, at least four seconds after the last request to ratings.fide.com in this run or in any of the session's manifests (`tools/data/politeness.py`, R75), the time logged at sending; the first refusal stops the run |
| `tools/data/assemble_greats_fixtures.py` | Writes `tests/fixtures/fide_greats/published_periods.json` from the greats' cached calculations and FIDE's lists: a sample of sixteen cases chosen by a fixed rule (ruling R79: at most 30 player-periods): one per rule of `src/layer0_greats/` (the 350-point rule, the 400-point rule with and without FIDE's mark, K 15, the 2014 cap), F-G06 for R74's rounding, the first period of each version, the periods either side of 1 July 2009 and 1 July 2014, and F-G15 and F-G16 either side of R80's switch of rounding (November 2018); no name, FIDE ID or event |

To rebuild what the `needs_data` scripts of `analysis/outputs.json` read: run `python3 tools/data/fetch_fide_lists.py <tc> 2015-02 2026-10` and `python3 tools/data/convert_fide_lists.py <tc>` for `standard`, `rapid` and `blitz`; `python3 tools/data/fetch_lichess_broadcasts.py 2020-01 2026-09` and `python3 tools/data/convert_broadcasts.py`; for the top-100 replay, `python3 tools/data/fetch_top100_calculations.py plan > PLAN` and `python3 tools/data/fetch_top100_calculations.py fetch PLAN`; for the greats (session ELO-9), the probe's pages with `tools/data/fetch_probe.py` (the keys and URLs `docs/research/DATA-PROBE_greats.md` lists), `python3 tools/data/fetch_fide_old_lists.py`, `python3 tools/data/convert_fide_old_lists.py`, `python3 tools/data/convert_fide_toparc.py`, `python3 tools/data/fetch_greats_calculations.py plan > PLAN` and `python3 tools/data/fetch_greats_calculations.py fetch PLAN`; then `python3 tools/checks/check_outputs.py --all`.
